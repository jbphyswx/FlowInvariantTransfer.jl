Unified Entry Point

FlowInvariantTransfer.calculate_energy_transfer — Function
calculate_energy_transfer(method, velocity_data, coords_or_ks; kwargs...)

Run the diagnostic method names and return its result container.

Arguments

  • method::AbstractEnergyTransferMethod: Which method to use:
    • SpectralFluxMethod(binning) — spectral flux Π(K) → SpectralFluxResult
    • ShellToShellTransferMethod(binning) — shell-to-shell T(n,m) → ShellToShellResult
    • ModeToModeTransferMethod(; invariant) — mode-to-mode S(k|p) → ModeToModeTriadResult
    • CoarseGrainingFluxMethod(filter, ℓ) — coarse-graining flux Π_ℓ(x) → CoarseGrainingFluxResult
    • TriadicOrthogonalDecompositionMethod(; nfft, noverlap, nmode) — called as calculate_energy_transfer(method, X; kwargs...) on snapshots X → TriadicOrthogonalDecompositionResult
  • velocity_data: For spectral methods, a complex array of size (ms..., D) containing Fourier coefficients; for coarse-graining, a tuple of D real physical-space arrays.
  • coords_or_ks: For spectral methods, a tuple of 1D wavenumber vectors; for coarse-graining, a tuple of 1D coordinate vectors.

Physical-space Cartesian data uses the 4-positional form calculate_energy_transfer(method, velocity_fields, coords, ms; transform, …), which routes on transform: a NUFFT library (FlowTransformBindings.NonuniformFFTsBackend() / FlowTransformBindings.FINUFFTBackend(), with Ls) reconstructs from scattered samples, while any other backend transforms uniform-grid data through FlowFieldSpectra (using FlowFieldSpectra; coords are the per-axis grid vectors). Coarse-graining has the same 4-positional scattered route. Spherical data uses calculate_energy_transfer(SphericalTransferMethod(), ζ, (θ, φ); lmax, …) (scattered, NUFSHT) or a regular colatitude–longitude grid (FastSphericalHarmonics).

Examples

using FlowInvariantTransfer, FlowFieldSpectra, FFTW
const FIT = FlowInvariantTransfer

# Spectral flux on a 32×32 periodic domain
N = 32; L = 2π
x = range(0.0, L; length=N+1)[1:N]
u = [cos(xi) * sin(yj) for xi in x, yj in x]
v = [-sin(xi) * cos(yj) + 0.3 * sin(2yj) for xi in x, yj in x]
û, ks = to_spectral((u, v), (x, x))                  # real fields: the half layout

result = calculate_energy_transfer(FIT.Types.SpectralFluxMethod(FIT.Types.LinearBinning(2π/L)), û, ks)

Physical → Spectral

The diagnostics take Fourier coefficients, so gridded physical data is transformed here once. A real field takes the half (rfft) layout: the non-redundant k₁ ≥ 0 coefficients, with ks[1] an rfftfreq axis. Complex input takes the full spectrum. Build the workspace once to reuse the plans and buffers across snapshots.

The domain is given either as per-axis ranges describing a uniform periodic box, or as a FlowGeometries grid. Passing a grid (using FlowFieldSpectra) selects the transform from the grid itself through FlowFieldSpectra.plan_spectrum — the tensor-product FFT on a uniform Cartesian grid, the FFT/NUFFT composite where some directions are stretched — and reads the period the grid declares.

FlowInvariantTransfer.to_spectral — Function
to_spectral(velocity_fields::Tuple, scatter_coords::Tuple, ms::Tuple; transform, Ls, tol = nothing,
            weights = nothing, execution = AutoBackend()) -> (velocity_hat, ks)

Scattered-Cartesian physical-space entry: reconstruct the Fourier coefficients velocity_hat on a uniform ms = (m₁,…,m_D) grid from velocity components sampled at scattered (non-uniform) points, through a NUFFT type-1 transform, and return them with the matching uniform wavenumber grid ks, the input of every Cartesian flux diagnostic. Real fields use the packed half of FlowTransformBindings' odd coefficient box: an even requested count is widened by one on that axis. Complex fields use the full ms box.

scatter_coords = (x, y[, z]) hold one coordinate per sample on each axis (each vector of length N, the number of samples); ms is the target uniform mode count per dimension. transform (required) names the NUFFT library: FlowTransformBindings.NonuniformFFTsBackend() (using NonuniformFFTs) or FlowTransformBindings.FINUFFTBackend() (using FINUFFT). For uniform-grid data use the 2-argument form with SpectralBackends.FFTSpectralBackend().

The coefficients are the quadrature û(k) = (1/∏L) Σⱼ wⱼ uⱼ e^{-ik·xⱼ}, with weights wⱼ the volume sample j stands for (Σw = ∏L). It is exact for a field band-limited to ms when the weights integrate every e^{iq·x} with |q_d| < m_d exactly. Without weights every sample stands for ∏L/N and û = type1(u)/N: exact for samples on the uniform L-grid (û = fft(u)/Nᵈ), and otherwise an estimate that weights each sample equally, so a region sampled densely counts for more than its volume.

tol sets the NUFFT accuracy (nothing: FlowTransformBindings.default_tolerance of the coordinates' float type). Ls (required) is the periodic domain size per dimension and fixes the wavenumbers k = 2πn/L: the samples live in [xₘᵢₙ, xₘᵢₙ+Lₐ) and under-span the period, so L cannot be inferred from them. execution = GPUBackend(dev) (dev a KernelAbstractions backend) builds the plan and buffers on the device, so the scattered → velocity_hat step runs there.

to_spectral(velocity_fields::Tuple, coords_vecs::Tuple; transform=SpectralBackends.AutoSpectralBackend()) -> (velocity_hat, ks)

Forward-transform physical-space velocity components sampled on a uniform, periodic, tensor-product Cartesian grid into the Fourier-coefficient input (velocity_hat, ks) consumed by every Cartesian flux diagnostic (calculate_spectral_flux, calculate_shell_to_shell_transfer, calculate_mode_to_mode_transfer, calculate_band_to_band_transfer, calculate_partial_fluxes, calculate_compressible_flux). This is the physical-space entry point for gridded data: the diagnostics operate on coefficients, so a real field is transformed here once with the package's û = fft(u)/Nᵈ normalization (so E(k) = ½|û|²) and the FFTW fftfreq wavenumber convention — you do not build û/ks by hand.

coords_vecs are one-dimensional ranges (x, y[, z]), each holding nₐ periodic samples x₁, x₁ + Δ, …, x₁ + (nₐ−1)Δ of the period L = nₐΔ. Other coordinate arrays need a FlowGeometries grid with an explicit period. Scattered (non-uniform) Cartesian data takes the 3-argument form with a NUFFT library (transform = FlowTransformBindings.NonuniformFFTsBackend() or FlowTransformBindings.FINUFFTBackend()), and spherical data calculate_spherical_transfer.

Keyword Arguments

  • transform::SpectralBackends.AbstractSpectralBackend = SpectralBackends.AutoSpectralBackend(): the analysis transform. SpectralBackends.FFTSpectralBackend() needs using FFTW (cuFFT is used automatically for device-array inputs); SpectralBackends.DirectSumSpectralBackend() is the dependency-free O(N²ᴰ) reference (tiny grids only).

Returns

(velocity_hat, ks) — complex coefficients shaped (ms..., D) in the input array's backend and their wavenumber axes. Real input takes the packed half; complex input takes the full spectrum.

Example

using FlowInvariantTransfer, FlowFieldSpectra, FFTW
û, ks = to_spectral((u, v), (x, y))
result = calculate_spectral_flux(û, ks)

Pass a scalar (density / pressure / passive scalar) as a 1-tuple: ρ̂, _ = to_spectral((ρ,), coords).

Spectral Flux

FlowInvariantTransfer.SpectralFlux.calculate_spectral_flux — Function
calculate_spectral_flux(velocity_hat, ks; binning, dealiasing=OrszagTwoThirds(), invariant=KineticEnergy(),
    decomposition=NoDecomposition(), transform=AutoSpectralBackend(), execution=AutoBackend(),
    advecting_hat=velocity_hat, geometry=IsotropicShells()) -> SpectralFluxResult

Compute the spectral energy transfer spectrum T(k) and the cumulative energy flux Π(K) from Fourier-space velocity data.

Arguments

  • velocity_hat: Complex array of size (ms..., D) — Fourier coefficients of the D velocity components on the spectral layout ks describes (ms = ns, or the half layout of a real field).
  • ks: Tuple of 1D physical-wavenumber vectors (matching FFTW fftfreq convention).

Keyword Arguments

  • binning::AbstractShellBinning: Shell binning strategy; default LinearBinning(Δk) with Δk the smallest nonzero |k| on any axis.
  • dealiasing::AbstractDealiasing=OrszagTwoThirds(): Apply 2/3 dealiasing rule when computing (u·∇)u.
  • invariant::AbstractInvariant=KineticEnergy(): the quadratic invariant whose transfer is binned.
  • decomposition::AbstractFieldDecomposition=NoDecomposition(): with a splitting decomposition the result is a NamedTuple of SpectralFluxResults, one per component, each against the full N̂.
  • transform::SpectralBackends.AbstractSpectralBackend: transform backend — SpectralBackends.AutoSpectralBackend() (default; FFTSpectralBackend() when FFTW is loaded), SpectralBackends.FFTSpectralBackend(), or SpectralBackends.DirectSumSpectralBackend() (no dependencies).
  • execution::ComputationalBackends.AbstractExecutionBackend=ComputationalBackends.AutoBackend(): how the transfer-density write and the mode→shell reduction are parallelised:
    • ComputationalBackends.SerialBackend() — host scalar reduction.
    • ComputationalBackends.ThreadedBackend() (requires using OhMyThreads) — the mode→shell scatter is split into chunks with per-chunk partial shell sums (race-free), an O(Nᴰ) parallel pass.
    • ComputationalBackends.DistributedBackend() (requires using Distributed) — the scatter is partitioned across worker processes and +-reduced; the nonlinear-term FFTs stay on the calling process. A grid too large for one node takes pencil_spectral_flux (PencilFFTs).
    • ComputationalBackends.GPUBackend(dev) (requires using KernelAbstractions) — the transfer density is written by a device kernel and reduced per shell on-device, so a device-resident field stays on the GPU; host fields are copied to dev once per call.
  • advecting_hat=velocity_hat: the advecting velocity of (u·∇)f.
  • geometry::AbstractShellGeometry=IsotropicShells(): the wavenumber coordinate the shells partition.
  • form::AbstractNonlinearForm=Advective(): Rotational() evaluates ω × u with fewer transforms, the same fluxes for a divergence-free velocity advecting itself under the 2/3 rule; it takes kinetic energy, enstrophy or helicity and no advecting_hat.

Returns

SpectralFluxResult with fields:

  • k_shells: Representative wavenumber per shell; shell_edges: the shell boundaries.
  • transfer_spectrum: T(kn) = −dEn/dt from the nonlinear term, the energy shell n gives to the other shells per unit time — a sum over the shell's modes.
  • flux: Π[n] — the energy shells 1…n pass to larger wavenumbers per unit time, the flux through shell_edges[n+1].

Physics

T(kn) = Σ{|k| ∈ shelln} Re{ û*(k) · N̂(k) } Π[n] = Σ{m ≤ n} T(k_m)

Positive Π: forward (downscale) cascade; negative Π: inverse (upscale) cascade.

References

  • Verma et al. (2002) [arXiv:nlin/0204027]
  • Alexakis, Mininni & Pouquet (2005)

FlowInvariantTransfer.SpectralFlux.calculate_scalar_flux — Function
calculate_scalar_flux(velocity_hat, scalar_hat, ks; binning, dealiasing=OrszagTwoThirds(), transform,
                      execution=AutoBackend(), geometry=IsotropicShells()) -> SpectralFluxResult

Compute the passive-scalar variance transfer spectrum T_θ(k) and flux Π_θ(K), for a scalar θ advected by the velocity u (∂_tθ + (u·∇)θ = κ∇²θ):

T_θ(k_n) = Σ_{|k|∈shell_n} Re{ θ̂*(k) N̂_θ(k) },   N̂_θ = FFT[(u·∇)θ],   Π_θ(K) = Σ_{k≤K} T_θ(k).

Scalar variance is conserved for incompressible u (Σ_k T_θ ≈ 0) and cascades forward in any dimension (Obukhov–Corrsin). Thin wrapper over calculate_spectral_flux with invariant = PassiveScalar() and advecting_hat = velocity_hat.

Arguments

  • velocity_hat: complex (ns..., D) velocity Fourier coefficients (the advecting field).
  • scalar_hat: complex scalar field, either (ns...) or (ns..., 1).
  • ks: tuple of nd 1D wavenumber vectors.

Shell-to-Shell Transfer

FlowInvariantTransfer.ShellToShellTransfer.calculate_shell_to_shell_transfer — Function
calculate_shell_to_shell_transfer(velocity_hat, ks;
    binning, dealiasing=OrszagTwoThirds(), invariant=KineticEnergy(),
    transform=SpectralBackends.AutoSpectralBackend(), execution=ComputationalBackends.SerialBackend(),
    advecting_hat=velocity_hat, geometry=IsotropicShells())
    -> ShellToShellResult

Compute the directed shell-to-shell kinetic energy transfer matrix T(n,m).

Arguments

  • velocity_hat: Complex array of size (ms..., D) — Fourier coefficients of the D velocity components on a periodic uniform grid.
  • ks: Tuple of nd 1D physical-wavenumber vectors.

Keyword Arguments

  • binning::AbstractShellBinning: Shell binning; default LinearBinning(Δk) with Δk the smallest nonzero |k| on any axis.
  • dealiasing::AbstractDealiasing=OrszagTwoThirds(): Apply 2/3 rule dealiasing.
  • transform::SpectralBackends.AbstractSpectralBackend: SpectralBackends.AutoSpectralBackend() (default; FFTSpectralBackend() when FFTW is loaded), SpectralBackends.FFTSpectralBackend(), or SpectralBackends.DirectSumSpectralBackend().
  • execution::ComputationalBackends.AbstractExecutionBackend: outer (mediator-loop) parallelism — ComputationalBackends.AutoBackend() (default), ComputationalBackends.ThreadedBackend() (OhMyThreads), ComputationalBackends.DistributedBackend(), or ComputationalBackends.GPUBackend(dev), which copies host fields to dev once per call.
  • invariant, advecting_hat, geometry: as for calculate_spectral_flux.

Returns

ShellToShellResult with:

  • transfer_matrix[n,m]: the rate at which shell n gives energy to shell m.
  • net_transfer[n] = Σm T(n,m) = −dEn/dt, the spectral transfer of shell n.

Algorithm (Alexakis–Mininni–Pouquet 2005 formulation)

For each pair of shells n and m: T(n,m) = Σ{k∈Sn} Re{ û*(k) · N̂m(k) } where N̂m(k) = FFT[(u · ∇)um], um = IFFT(û · χm): the full velocity advects the shell-m field. For a divergence-free u, ∫un·(u·∇)um = −∫um·(u·∇)u_n, so T(n,m) + T(m,n) = 0 exactly (antisymmetry).

Cost

One advection per mediator shell: O(Nshells · Nᴰ log N) with FFTW, O(Nshells · N²ᴰ) by direct sums.

References

  • Verma et al. (2002), arXiv:nlin/0204027
  • Alexakis, Mininni & Pouquet (2005)

Mode-to-Mode Triad Transfer

FlowInvariantTransfer.ModeToModeTransfer.calculate_mode_to_mode_transfer — Function
calculate_mode_to_mode_transfer(velocity_hat, ks; invariant=KineticEnergy(), dealiasing=OrszagTwoThirds(),
                                transform=AutoSpectralBackend(), execution=AutoBackend(),
                                advecting_hat=velocity_hat)
    -> ModeToModeTriadResult

Mode-resolved triad transfer S(k|p) between the stored coefficients ("slots") of the spectral layout — the rate at which slot k gives the chosen quadratic invariant to the slot field u_p(x) = w(p)·Re{û(p) e^{ip·x}} (mediated by q = k−p), the part of −dE(k)/dt that advection of u_p accounts for:

S(k|p) = Re{ û*(k) · [(u·∇)u_p]^(k) }   (generalised per invariant via `transfer_density!`).

w(p) is the number of full-spectrum modes slot p stands for (1 on a full layout; on a half layout 2 on the interior of the halved axis, where the slot also stands for its mirror −p), returned as result.weights; the slot fields sum to u. It is the finest object in the reduction hierarchy S(k|p) → T(K,Q) (shell-to-shell) → T(k), Π(K) (spectral flux):

  • reduces: Σ_p S(k|p) = T(k), the spectral transfer (calculate_spectral_flux);
  • antisymmetric (divergence-free, dealiased): w(k)S(k|p) = −w(p)S(p|k), since w(k)S(k|p) = ⟨u_k·(u·∇)u_p⟩ and ∫(u·∇)(u_k·u_p) = 0 — S(k|p) = −S(p|k) on a full layout;
  • conserves: Σ_k Σ_p w(k)S(k|p) = 0.

Cost & memory

One nonlinear-term evaluation per slot p: O(N_scales) evaluations, O(N_scales · Nᴰ log N) time with SpectralBackends.FFTSpectralBackend, and an O(N_scales²) result tensor, where N_scales = prod(ms) is the number of stored slots. The aggregates come cheaper from calculate_spectral_flux (T(k), Π) or calculate_shell_to_shell_transfer (T(n,m)).

Keyword arguments

  • invariant::AbstractInvariant: which quadratic invariant (default KineticEnergy()).
  • dealiasing::AbstractDealiasing=OrszagTwoThirds(): dealiasing of the nonlinear term; under PaddedThreeHalves() each slot's term is formed on the padded grid.
  • transform::SpectralBackends.AbstractSpectralBackend: AutoSpectralBackend() (default, the FFT when FFTW is loaded).
  • execution::ComputationalBackends.AbstractExecutionBackend: parallelism over the slots p (AutoBackend() default; threaded, distributed and GPU through their extensions). Under GPUBackend(dev) host fields are copied to dev once per call, and the result arrays are on dev.
  • advecting_hat=velocity_hat: the advecting velocity of (u·∇)u_p.

Returns

ModeToModeTriadResult with weights (w, shape ms), net_transfer (T(k), shape ms) and transfer (the resolved S(k|p), shape (ms..., ms...)).

Smooth Band-to-Band Transfer

FlowInvariantTransfer.BandTransfer.calculate_band_to_band_transfer — Function

Smooth band-to-band transfer T(n,m) of a quadratic invariant between the graded spectral bands (Eyink & Aluie 2009) — the smooth-filter analogue of calculate_shell_to_shell_transfer. Accepts an advecting_hat (primary field can be a passive scalar advected by the velocity) and an anisotropic geometry. Under execution = GPUBackend(dev) host fields are copied to dev once per call. See calculate_band_to_band_transfer! for the in-place, workspace-reusing variant.

Decompose the kinetic-energy flux into per-component partial fluxes Π^{s_k s_p s_q}(K), where each of the three fields in a triad interaction is one component of a velocity decomposition u = Σ_s u_s; channels is keyed by the component-name triple (s_k, s_p, s_q) and total is their sum. The channel term depends on the decomposition:

  • HelicalDecomposition (3-D) — the rotational form of Alexakis (2017, Eq. 17), Π^{s₁s₂s₃}(K) = −⟨u^{s₁}_{K<}·(u^{s₂} × ω^{s₃})⟩:

    T^{s_k s_p s_q}(k) = Re{ û_{s_k}*(k) · [ω_{s_q} × u_{s_p}]^(k) },   ω_s = ∇ × u_s.

    s_k is the component whose energy the term changes, s_p the velocity of the cross product and s_q the field whose vorticity it carries. The helical components are solenoidal, so the channels sum to the flux of the solenoidal part of u.

  • every other decomposition — the advective form

    T^{s_k s_p s_q}(k) = Re{ û_{s_k}*(k) · [(u_{s_p}·∇) u_{s_q}](k) },

    whose channels sum to the full flux. For HelmholtzDecomposition the off-diagonal channels are the rotational↔divergent cross-flux, zero for incompressible flow.

triadic_orthogonal_decomposition(X; kwargs...)

Compute the Triadic Orthogonal Decomposition of data array X.

TOD decomposes triadic (three-wave) nonlinear interactions in time-series data, identifying coherent flow structures that optimally capture spectral momentum transfer. It produces a mode bispectrum (singular values quantifying coupling strength per frequency triad), convective/recipient modes, and a modal energy budget.

  • X::AbstractArray: Data of size (nt, nvar, spatial_dims...). First dimension is time, second is variable indices, remaining are spatial.

  • window: Temporal window. Vector → used directly. Integer → Hamming of that length. nothing → auto Hamming (length = 2^floor(log2(nt/5)), capped at 256).
  • weight: Spatial inner-product weight (same spatial dims as X). nothing → uniform.
  • noverlap: Block overlap in snapshots. nothing → 50% of window length.
  • dt: Time step between snapshots. nothing → 1/nDFT (frequency index output).
  • Q: Quadratic nonlinearity (q1, q2) -> product of two (nVar, nx, nBlks) realizations, q1 at f_k = f_n − f_l and q2 at f_l, returning (nx, nState, nBlks). Default: the elementwise product, Q(q1, q2)[ix, iv, b] = q1[iv, ix, b]·q2[iv, ix, b], which takes no derivative.

  • mean: ZeroMean() (default), BlockMean(), or an array containing the mean to subtract.
  • output: ModesOnly() (default), WithCoefficients(), or WithAuxiliaryModes().

  • auxiliary_modes: Donor/catalyst modes (or nothing).
